# 大乐透下一期开奖训练模型设计

## 目标

将当前“Milvus 相似历史期检索 + 时间衰减加权”的单一参考号码生成逻辑，替换为同时输出三组结果的下一期开奖预测：一组来自历史序列训练的逻辑回归模型，一组来自前区、后区独立向量的相似转移模型，另一组使用滚动回测选出的权重动态融合前两组分数，作为页面主推荐。

系统统一预测下一期号码，不再让用户选择“最近一期”或输入自选号码。后端同时生成三种算法结果，页面通过模型下拉框选择并展示其中一组前区 5 个和后区 2 个号码。模型输出仍属于历史数据分析结果，不表达或承诺中奖概率。

同时扩大开奖采集范围：定时采集与管理端手动采集均默认读取中国体彩网最近 30 页。按当前每页 30 期计算，单次最多处理约 900 期数据。

## 总体架构

保留 PostgreSQL 作为开奖数据和模型数据的主库。逻辑回归模型从 PostgreSQL 读取生效参数；相似转移模型使用 Milvus 中独立的前区、后区向量索引，并从 PostgreSQL 读取命中期的下一期开奖详情。

后端新增五个职责清晰的模型组件：

- `TrainingDatasetBuilder`：按开奖日期构造时间序列训练样本，确保每个样本只使用目标期之前的数据。
- `NextDrawModelTrainer`：训练、验证前区和后区的正则化逻辑回归模型。
- `VectorTransitionModelTrainer`：按时间回测相似转移算法并记录验证指标和索引水位。
- `DynamicEnsembleTrainer`：基于两种基础模型的滚动回测结果，分别选择前区和后区融合权重。
- `NextDrawPredictionService`：读取同一批次生效的三类模型，分别输出下一期号码和各号码得分。

两种基础模型完成训练或回测后，与动态融合配置一起写入 PostgreSQL。预测请求不在用户请求线程中训练模型；逻辑回归直接推理，相似转移模型执行 Milvus 检索和 PostgreSQL 详情查询，动态融合模型只组合前两种模型已经生成的候选号码分数。

## 开奖采集

### 配置

`lottery.dlt` 增加并使用以下配置：

```yaml
lottery:
  dlt:
    page-size: ${DLT_FETCH_PAGE_SIZE:30}
    page-count: ${DLT_FETCH_PAGE_COUNT:30}
```

- `page-size` 表示每页期数，默认 30。
- `page-count` 表示一次采集页数，默认 30。
- 定时采集调用默认配置，因此默认读取 30 页。
- 管理端手动采集接口接受可选 `pageCount`，未传时使用配置值 30，允许范围为 1 至 100。

### 分页读取

`SportteryDltClient` 按 `pageNo=1..pageCount` 顺序请求官方接口。遇到空列表时提前停止。所有页结果使用期号去重，再交给 `DrawStore` 幂等写入 PostgreSQL。

管理员接口保持 `POST /api/v1/admin/dlt/sync`，增加可选查询参数：

```text
POST /api/v1/admin/dlt/sync?pageCount=30
```

响应继续返回抓取数量、变更数量和执行结果。

## 训练样本

### 数据顺序和最低要求

- 只使用 PostgreSQL 中有效的历史开奖，按 `drawDate`、`id` 升序排列。
- 特征窗口固定为目标期之前的 20 期。
- 至少需要 100 期历史开奖。少于 100 期时不生成模型，并返回“训练样本不足”的明确状态。
- 期号只用于追踪模型训练位置，不作为数值特征。

### 样本构造

对每个可预测的目标期，为前区 1 至 35 和后区 1 至 12 的每个候选号码分别构造二分类样本。标签表示该号码是否出现在目标期开奖中。

每个候选号码使用以下特征，所有特征只读取目标期之前的开奖：

1. 上一期是否出现。
2. 最近 5 期出现频率。
3. 最近 10 期出现频率。
4. 最近 20 期出现频率。
5. 当前遗漏期数，最大截断为 20，再归一化到 0 至 1。
6. 最近 5 期频率与此前 15 期频率的差值。

模型内部另含偏置项。前区和后区分别训练一组参数，不使用候选号码编号作为特征，避免让模型记忆没有业务依据的号码固有偏好。

## 模型算法

### 模型一：正则化逻辑回归

使用纯 Java 实现的 L2 正则化二元逻辑回归：

- 前区模型对候选号码输出出现分数，后区模型独立输出分数。
- 使用类别权重缓解“未出现”样本显著多于“出现”样本的问题。
- 使用固定训练轮数、学习率和正则化参数，训练过程不使用随机初始化，确保相同数据得到可复现结果。
- 不增加 Python 服务，也不在运行环境安装独立机器学习平台。

训练完成后，使用同一特征定义对最新 20 期开奖中的全部候选号码打分。前区选择得分最高的 5 个，后区选择得分最高的 2 个；分数相同时按号码升序，最终号码按升序返回。

### 模型二：分区向量相似转移

每期开奖拆成两个整体向量：

- 前区使用 35 维向量，命中的 5 个位置分别写入 `1/sqrt(5)`，其余位置为 0。
- 后区使用 12 维向量，命中的 2 个位置分别写入 `1/sqrt(2)`，其余位置为 0。
- 两个向量均已归一化，Milvus 使用内积 `IP` 时，前区得分等于重合号码数除以 5，后区得分等于重合号码数除以 2。

预测下一期时，分别执行以下过程：

1. 使用最新一期前区向量检索前区近邻，使用最新一期后区向量检索后区近邻。
2. 排除最新一期本身，以及在时间序列中没有下一期开奖的命中记录。
3. 每个命中记录不直接贡献自身号码，而是取得该记录之后的下一期开奖。
4. 前区使用前区相似度为下一期开奖的前区号码加权，后区使用后区相似度为下一期开奖的后区号码加权；每个候选号码的累计权重除以全部有效近邻权重，得到 0 至 1 的分数。
5. 每个分区默认使用相似度最高的 30 个有效转移样本。
6. 汇总后分别选择前区最高 5 个、后区最高 2 个；分数相同时按号码升序。

前区和后区独立检索、独立选择转移样本，不把两个分区的相似度合并为一个总分。完全相同的历史号码可以作为有效近邻，只要该历史期之后存在真实开奖。

如果某个分区的有效近邻总权重为 0，则该模型本次不能生成完整结果，预测接口返回模型不可用，而不是使用随机号码补齐。

### 模型三：动态融合

动态融合不再训练第三套候选号码参数，而是组合逻辑回归和分区向量相似转移模型的候选号码分数：

```text
融合分数 = 逻辑回归分数 × 逻辑回归权重 + 相似转移分数 × 相似转移权重
```

- 前区和后区分别选择权重，两个分区互不共用权重。
- 每个分区的两个权重均位于 0 至 1，且权重之和等于 1。
- 权重候选按 `0.00, 0.05, ... , 1.00` 枚举逻辑回归权重，相似转移权重为其补数。
- 以全部滚动验证期的平均二分类对数损失最小为首要选择条件；对数损失相同时，选择平均命中数更高的组合；仍相同时，选择逻辑回归权重更高的组合，确保结果可复现。
- 如果某个基础模型在一个分区上的对数损失不优于均匀随机基线，并且平均命中数也不优于随机基线，而另一基础模型至少有一项更优，则该分区将较弱模型权重固定为 0。
- 如果两种基础模型在某个分区都没有超过随机基线，新的融合版本不替换已有生效批次；系统首次训练时允许激活对数损失最低的组合，但在接口响应中标记该分区未超过随机基线。

生成结果时，前区取融合分数最高的 5 个号码，后区取最高的 2 个号码；分数相同时按号码升序，最终号码按升序返回。融合配置必须记录所引用的两个基础模型版本，禁止组合不同训练批次或不同开奖水位的基础模型。

## 滚动时间验证

所有可用目标期按时间顺序进行扩展窗口验证：

- 最早的 60% 目标期作为第一个训练窗口。
- 剩余 40% 按时间顺序平均切分为 5 个连续验证折；不能整除时，多出的目标期从较早的验证折开始依次分配。
- 每一折都只使用该折开始之前的目标期训练逻辑回归；相似转移回测也只能使用该折目标期之前已经完整发生的历史转移。
- 完成一折后，将该折加入历史窗口，再训练或回测下一折，形成扩展窗口。
- 5 折预测分数和真实标签合并计算验证指标，并供动态融合模型选择前区、后区权重。
- 完成验证后，逻辑回归使用全部样本训练生产参数，相似转移模型使用全部可用历史建立生产索引水位，动态融合保存从滚动验证中选出的权重。

三种模型分别记录以下验证指标：

- 前区候选号码二分类对数损失。
- 后区候选号码二分类对数损失。
- 验证期中前区每期平均命中数。
- 验证期中后区每期平均命中数。
- 均匀随机基线：前区平均命中数 `25/35`，后区平均命中数 `4/12`。

均匀随机基线的候选号码概率固定为前区 `5/35`、后区 `2/12`，用相同公式计算对数损失。逻辑回归回测严格按照特征窗口构造验证样本。相似转移模型回测单个目标期时，只允许使用该目标期之前的历史记录，并且近邻记录的“下一期”也必须早于目标期，防止从 Milvus 全量索引中读取未来结果。回测可在 Java 内存中对受限历史前缀计算相同的向量内积，生产推理再使用 Milvus 索引。

指标用于观察模型是否退化，不作为中奖率证明。三类候选版本作为同一训练批次共同决定是否激活：融合模型任一分区的两种基础模型都未超过随机基线时，仍保存本次训练记录，但不替换上一生效批次；系统首次训练允许生效，以保证系统具有可运行的初始版本，同时在响应中明确展示验证指标和基线判断。

## 模型持久化

新增 Flyway 迁移和 `prediction_model` 表，保存：

- 模型类型：`LOGISTIC_REGRESSION`、`VECTOR_TRANSITION` 或 `DYNAMIC_ENSEMBLE`。
- 模型版本和算法版本。
- 训练批次版本；同一次训练生成的三类模型使用相同批次版本。
- `ACTIVE` 或 `INACTIVE` 状态。
- 模型配置 JSON；逻辑回归保存前区、后区权重，相似转移模型保存向量版本和近邻数量，动态融合保存前区、后区融合权重及引用的两个基础模型版本。
- 特征窗口大小。
- 使用的开奖期数和训练样本数。
- 训练截至的开奖 ID、期号和日期。
- 训练时间。
- 四项验证指标及随机基线。

每种模型类型在任何时刻最多有一个 `ACTIVE` 版本。新批次的两种基础模型和动态融合配置均完成并持久化后，在同一事务中停用上一批次的三个模型并激活新批次，避免预测请求读取到半成品或混用不同开奖水位。

任一基础模型训练或回测失败、动态权重选择失败，都不删除或停用现有生效批次。其余已成功生成的候选记录保持 `INACTIVE`，失败原因写入应用日志，采集到的开奖数据仍然保留。

## 训练触发

### 自动训练

- 应用启动时，如果任一模型没有生效版本、三个生效模型不属于同一批次，或任一生效模型的最后开奖 ID 早于数据库最新开奖，则统一训练两种基础模型并选择动态融合权重。
- 定时采集或管理员手动采集结束后，只要存在新增或修正的开奖记录，就自动训练两种基础模型并选择动态融合权重。
- 人工补录或修正开奖后同样触发自动训练。
- 同一 JVM 内只允许一个训练任务运行；并发触发返回“训练进行中”，不重复启动训练。

自动训练在开奖事务提交后执行。训练失败不会回滚开奖记录。

### 管理员手动训练

新增接口：

```text
POST /api/v1/admin/dlt/model/retrain
```

该接口强制使用当前 PostgreSQL 历史数据重新训练逻辑回归模型、回测相似转移模型并选择动态融合权重，返回三种模型各自的训练状态、模型版本、开奖期数、样本数、验证指标和提示信息。

管理端“数据同步”页面增加“手动重训模型”按钮，与“手动同步开奖”分开显示，并展示最近一次训练结果。

## 预测接口

保留现有地址：

```text
POST /api/v1/dlt/predictions
```

请求不再需要输入类型、自选号码或 `topK`。前端提交空对象，后端使用最新开奖同时生成逻辑回归、相似转移和动态融合三组下一期参考号码。

响应包含：

- 统一的生成时间、依据的最新期号和风险提示。
- `predictions` 数组，固定按逻辑回归、相似转移、动态融合排序。
- 每个模型各自的前区 5 个号码和后区 2 个号码。
- 每个模型各自的前区 1 至 35、后区 1 至 12 分数。
- 每个模型的类型、中文名称、版本、训练时间和训练开奖期数。
- 每个模型训练或回测截至的期号。
- 每个模型的四项验证指标和随机基线。

动态融合结果额外返回前区和后区的两个基础模型权重、引用的基础模型版本，以及是否超过随机基线。移除响应中的 `similarDraws`。任一模型未就绪、三个模型不属于同一训练批次或历史开奖少于 100 期时，接口返回 HTTP 503 和中文提示，避免页面把不完整结果误认为三模型对比。接口不回退到旧的相似历史期加权算法。

## 前端调整

预测页面移除：

- “最近一期 / 自定义号码”单选项。
- 前区、后区自选号码输入框。
- 相似历史期表格。

页面保留“生成下一期参考号码”按钮，并增加预测模型下拉框，选项为“逻辑回归模型”“分区向量相似转移模型”和“动态融合模型”。默认选择“动态融合模型（主推荐）”；切换选项只改变本地展示，不重复请求后端。结果区只展示当前模型的一张卡片，包含号码、训练截至期号、训练期数、模型版本和验证指标；动态融合结果额外展示前区、后区各自的融合权重。风险提示明确说明三种结果都基于历史数据，开奖结果具有随机性。

管理端数据同步页面：

- 手动开奖同步默认请求 30 页，可填写 1 至 100 的页数覆盖默认值。
- 增加“手动重训模型”按钮。
- 分别显示采集结果和训练结果，避免将采集成功与模型训练成功混为同一状态。

## 现有 Milvus 流程

开奖记录入库后继续维护 `vector_status`、失败重试和管理员重试接口。除现有 47 维联合向量 collection 外，新增一个分区转移 collection，包含：

- `draw_id`：PostgreSQL 开奖主键。
- `front_vector`：35 维前区向量，使用独立 `IP` 索引。
- `back_vector`：12 维后区向量，使用独立 `IP` 索引。

同一条开奖记录的联合向量、前区向量和后区向量全部写入成功后，`vector_status` 才标记为 `READY`。任一写入失败均标记为 `FAILED`，由启动补偿或管理员重试恢复。

逻辑回归预测不依赖 Milvus。相似转移和动态融合预测依赖新的分区转移 collection；Milvus 检索失败时整个三模型预测接口返回 HTTP 503，避免前端只展示部分结果。现有联合向量 collection 和相关类继续保留。

## 错误处理

- 官方分页接口任一页请求失败时，本次采集返回失败，已经完成的数据库事务不删除历史数据。
- 样本少于 100 期时训练返回 `INSUFFICIENT_DATA`。
- 已有训练运行时返回 `TRAINING_IN_PROGRESS`。
- 任一基础模型训练、回测或融合权重选择异常时，返回对应环节的 `FAILED` 状态，并保留上一完整生效批次。
- 任一模型无生效版本、模型批次不一致或融合模型引用的基础版本不一致时，预测返回 HTTP 503。
- Milvus 分区向量检索失败时预测返回 HTTP 503。
- 模型权重损坏或特征版本不兼容时拒绝推理并返回 HTTP 503。

## 测试与验收

后端测试覆盖：

- 30 页采集、空页提前结束、跨页期号去重和 `pageCount` 边界。
- 时间窗口特征不读取目标期或未来开奖。
- 逻辑回归训练可复现、权重长度正确、分数位于 0 至 1。
- 前区 35 维、后区 12 维编码及 Milvus 独立检索的相似度正确。
- 相似转移使用近邻之后的开奖，不把近邻自身当成预测号码。
- 5 折扩展窗口的边界正确，三种模型均不读取未来数据，验证指标计算正确。
- 动态融合前后区独立选权，权重和为 1，网格搜索及平局规则结果可复现。
- 弱于随机基线的基础模型可被赋予 0 权重，首次训练和已有生效批次时的激活规则正确。
- 三类新模型按同一批次原子激活，任一环节失败时保留完整旧批次，并覆盖样本不足和并发训练状态。
- 三种预测都选择前区 5 个和后区 2 个，分数相同按号码升序。
- 自动训练触发与管理员手动训练接口。

前端执行类型检查和生产构建，并人工检查：

- 预测页不再显示自选号码或相似历史期。
