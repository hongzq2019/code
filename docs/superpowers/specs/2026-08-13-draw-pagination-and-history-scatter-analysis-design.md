# 开奖分页与历史点位分析设计

## 目标

为历史开奖列表补充分页交互，并新增“历史点位分析”菜单。分析页允许选择开始和结束日期，默认展示最近 12 个月的大乐透号码双散点图。

## 范围

- 历史开奖列表改为每页 20 条，使用既有 `GET /api/v1/dlt/draws` 的 `page`、`size` 和 `issueNo` 参数。
- 新增公开路由 `/analysis` 和顶部菜单“历史点位分析”。
- 新增按日期范围查询开奖的接口，仅服务于历史点位分析。
- 使用 Apache ECharts 6.1.0 的按需模块实现前区、后区双散点图。

不修改预测、Milvus 同步、账户审核和开奖写入流程；不新增测试文件。

## 历史开奖分页

`Draws.vue` 保留期号筛选。页面维护当前页、固定页大小 20、总条数和表格数据：

- 首次加载请求第 1 页。
- 提交新的期号筛选时重置到第 1 页后请求。
- Element Plus 分页控件展示上一页、页码、下一页和总条数。
- 接口失败与空数据继续由 `PageState` 显示。

后端现有 `DrawPageResponse` 已包含 `items`、`page`、`size`、`total`，无需改变该接口契约。

## 历史点位分析

### 路由与默认范围

`/analysis` 为公开数据分析路由，与首页、历史开奖并列展示。页面初始化时计算本地日期：结束日期为当天，开始日期为同一日期向前一年；立即执行一次查询。

日期选择器使用日期范围模式，提交时必须同时包含开始和结束日期。结束日期早于开始日期由后端返回参数错误，并显示统一错误提示。

### 数据接口

新增接口：

`GET /api/v1/dlt/draws/analysis?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD`

控制器解析 ISO 日期并校验范围，调用 `DrawStore.findByDateRange`。仓储层通过 `draw_date BETWEEN startDate AND endDate` 按开奖日期升序查询。接口返回 `ApiResponse<List<DrawResponse>>`，复用既有开奖 DTO，避免创建重复的数据模型。

空范围返回空数组而非错误；非法日期或反向范围返回统一参数错误响应。

### 双散点图

新增 `DrawScatterChart.vue`，接收日期升序的 `Draw[]`：

- 上图为“前区号码”，横轴为开奖日期、纵轴 1–35，红色散点。
- 下图为“后区号码”，横轴为开奖日期、纵轴 1–12，蓝色散点。
- 两个图使用相同时间范围但独立纵轴范围，避免后区点位被前区刻度压缩。
- 每个点保留期号、日期、号码，悬停提示显示这些信息。
- 组件在挂载时初始化 ECharts，数据变化时更新 option，容器尺寸变化时 resize，卸载时 dispose。

仅从 `echarts/core` 按需注册 `ScatterChart`、`GridComponent`、`TooltipComponent`、`LegendComponent` 和 `CanvasRenderer`，避免引入完整图表包。

## 前端状态与错误处理

分析页在加载中显示骨架；无记录时显示空状态；请求失败时显示后端错误消息。图表仅在成功返回且存在记录时渲染，避免向空容器初始化图表。

## 验证

- 不新增测试文件，遵循既有要求。
- `mvn package` 验证日期范围接口、已有测试和后端打包。
- `npm run build` 验证 ECharts 类型、Vue 页面、路由和生产构建。
- 人工检查：`/draws` 翻页与筛选重置；`/analysis` 默认近 12 个月、切换日期范围、前后区双图、空数据和错误状态。
